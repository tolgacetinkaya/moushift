# Moushift 0.14.5 — side view and clearer learning

- Hide the battery icon and label whenever Windows supplies no valid percentage, in both the gallery and selected-mouse screen. Valid percentages, including 0%, remain visible.
- Switch between the existing top artwork and an original generic left-side drawing in the selected-device and embedded learning workspaces. A taught position retains its elevation across save/restart; old positions remain on the top drawing.
- Replace ambiguous rescan wording with **Refresh input discovery**. It refreshes available interfaces; **Listen for button** performs the actual capture.
- Show a release guard, 30-second listening countdown, selected-connection data arrival and 0/2, 1/2, 2/2 confirmation. Explain separately when nothing arrives, data arrives without a recognized button, or only one press is confirmed. Surface discovery access errors without claiming the hardware sends no input.
- Explicitly label a driverless Circle binding as **Click Circle + original click** in the saved action summary. This release does **not** add per-device click suppression. No driver, package or vendor protocol is installed.

Themes, per-mouse/application bindings and existing learned identities are retained. The side drawing is illustrative; it is not evidence of a particular model's button capabilities. Arbitrary HID assignments remain inactive drafts.

## Verification

Core and Windows tests cover persisted elevation, legacy top-view defaults, selected-device isolation and existing input behavior. Offscreen WPF checks cover both themes, hidden unknown/visible empty batteries, side-view transforms, embedded learning, no-input/partial-input retry and existing profile preservation. Physical sniper capture and per-mouse suppression are not verified or claimed fixed.

# Moushift 0.14.2 — workspace layout

The device gallery, button positions and Click Circle now have distinct working areas while keeping the existing light/dark palette and per-mouse profiles.

## Changes

- Drag the divider to resize the selected mouse's settings panel. The width survives restart.
- Collapse navigation to an icon rail with the arrow at the top. Its state is remembered separately from mouse settings.
- Click a mouse's name/card to select it; click its drawing to open button positions in the center. **All mice** returns to the gallery.
- The Buttons inspector contains assignments without a duplicate miniature Circle, repeated position subtitles or nested list scrollbars. The button editor has an outlined **Close** button.
- **Click Circle** opens the full editor inside the main window. The Circle is centered, the draggable action library is on the right, and its divider is resizable too. Folders, application profiles, drag feedback, undo/redo and scoped saves use the existing editor.
- Leaving a changed Circle draft asks before discarding it. Saving only updates that mouse's Circle profiles. A disconnected connection does not discard an open Circle draft.

## Download

Download `Moushift-0.14.2-win-x64.zip`, extract the entire folder and run `Moushift.exe`. Windows 10/11 x64; .NET and Windows Desktop runtimes are included. No additional library or input driver is installed. Compare the ZIP's SHA256 with `SHA256SUMS.txt`.

## Preserved behavior and limits

Existing assignments, application profiles and appearance stay in the compatible data directory; no reset or migration is needed. The new `workspace.json` contains only layout preferences.

**Driverless Circle still preserves the original trigger click.** In particular, assigning Circle to the wheel button does not suppress middle-click or a browser's autoscroll. The assignment form now states this explicitly. Source-specific suppression remains available only through the separately configured exclusive input backend; this update does not install it. Other direct remaps and arbitrary learned HID drafts retain their documented limits.

Validation uses isolated offscreen WPF and source-routing tests. Real-device acceptance, OLE pointer interaction and the reported Corsair double-click issue are not established by those checks.

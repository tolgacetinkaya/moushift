# Moushift 0.14.1 — first public preview

Configure each mouse independently and open your shortcuts from a compact Click Circle.

## Download and run

1. Download `Moushift-0.14.1-win-x64.zip` from the release assets.
2. Extract the complete folder and run `Moushift.exe`.
3. Windows 10/11 x64 is required. **The .NET and Windows Desktop runtimes are included**: no separate .NET installation or SDK is needed. Keep all extracted files together.
4. Choose a mouse, assign Click Circle to a standard button, then choose **Enable Circle**. Test it outside the editor.

`SHA256SUMS.txt` contains the ZIP checksum. In PowerShell, run `Get-FileHash .\Moushift-0.14.1-win-x64.zip -Algorithm SHA256` and compare it with that file.

## Included

- Independent default and application profiles for each mouse connection.
- Click Circle with drag/drop actions, folders, shortcuts and undo/redo.
- Generic HID button discovery with manually selected positions on the mouse drawing.
- Side-by-side device gallery, a selected-device inspector, and light/dark themes.

## Existing Clickloom users

Clickloom is now Moushift. The title bar, tray menu, executable and portable archive use the new name.

Existing mouse assignments, device/application profiles and appearance are preserved in the existing `%LOCALAPPDATA%/Clickloom` data directory. The `CLICKLOOM_DATA_DIR` development override and the single-instance identity remain compatible with previous local builds. No settings migration or reset is required.

- Run `Moushift.exe`, or build locally and use `Start-Moushift.cmd`. The old launcher forwards to the new one.
- Side-by-side mouse gallery and selected-device inspector, light/dark appearance, Click Circle folders and per-application profiles are retained.
- Driverless Circle still observes five standard buttons from the exact source mouse. Original clicks still reach Windows. Other remapping and firmware-only controls retain their documented limitations.

This Windows x64 preview includes its runtime and does not install a driver. Fixture/offscreen checks are separate from physical device acceptance.
